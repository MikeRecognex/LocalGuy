# Auto-Tagging Implementation Plan

## Context

The LocalGuy blog is an Eleventy 3.x static site where content is generated by an n8n workflow that commits markdown posts to GitHub. The n8n workflow uses Claude Haiku to generate post content including tags, but the tags are poor quality — freeform, inconsistent, and missing obvious entities like company names, model families, and tools. These tags feed the landing page's top 15 tag cloud and tag pages, so they need to be good.

## Goal

Implement build-time auto-tagging in Eleventy that scans each post's content against a curated taxonomy dictionary, extracting companies, models, tools, and topics as canonical tags. This replaces reliance on Haiku-generated tags without changing the n8n pipeline.

## Codebase Facts

- Eleventy v3.1.2, CJS mode (`require()` throughout)
- Posts: `content/posts/YYYY-MM-DD/*.md` with YAML frontmatter tags
- Existing `content/posts/posts.json` sets layout, permalink, comments
- No existing `posts.11tydata.js`
- Tag cloud: `eleventy.config.js` `tagCloud` filter → landing page sidebar (top 15)
- Tag pages: `content/pages/tags.njk` paginates over `collections`, generates `/tags/{tag}/`
- `_validatePosts` collection requires `tags` field in frontmatter (line 252)
- Global `eleventyComputed` already set via `addGlobalData` for draft exclusion (line 221)
- Input dir is `content`, includes `../_includes`, data `../_data`, output `_site`

## Step 1: Create the tag taxonomy dictionary

Create `_data/tag-taxonomy.js` (outside `content/` to avoid Eleventy processing it as a template).

This is a CJS module exporting an object with four categories:
- **companies**: Meta, Google, Apple, NVIDIA, AMD, Intel, Qualcomm, Microsoft, Mistral, Anthropic, OpenAI, Hugging Face, Stability AI, Groq, Cerebras, Mozilla, Nomic, LM Studio, Samsung, ByteDance, Alibaba, Cohere, etc.
- **models**: Llama, Gemma, Phi, Qwen, DeepSeek, Mixtral, Whisper, Stable Diffusion, Flux, GLM, MiniMax, Gemini, GPT-OSS, etc.
- **tools**: Ollama, llama.cpp, vLLM, MLX, ExLlama, TGI, LocalAI, GPT4All, KoboldCpp, Jan, Open WebUI, LlamaFile, MCP, LangChain, ONNX, TensorRT-LLM, PaddleOCR, etc.
- **topics**: quantisation, fine-tuning, RAG, benchmarks, inference, memory optimisation, agents, coding, multimodal, voice, privacy, edge deployment, open-source, speculative decoding, distillation, structured output, hardware, security, etc.

Each entry maps a canonical slug to an array of **regex patterns** with word boundaries:

```js
module.exports = {
  companies: {
    nvidia: [/\bnvidia\b/i],
    amd: [/\bamd\b/i, /\bradeon\b/i, /\binstinct\b/i],
    // ...
  },
  // ...
};
```

Using `\b` word boundaries instead of space padding — this correctly matches "AMD," "AMD." "AMD's" and "AMD" at start/end of string without false positives on "made".

## Step 2: Create the Eleventy computed data file

Create `content/posts/posts.11tydata.js` alongside the existing `posts.json`.

This file:
1. Requires `../../_data/tag-taxonomy.js`
2. Uses `fs.readFileSync(data.page.inputPath, 'utf8')` to get raw content — this is the **primary approach** because in Eleventy 3, `data.content` is not reliably available when computed data runs (content hasn't been rendered yet at that point in the data cascade)
3. Strips YAML frontmatter from the raw file content
4. Concatenates title + description + body into searchable text
5. Scans against all taxonomy regex patterns
6. Merges extracted tags with existing frontmatter tags
7. Returns deduplicated, sorted array

```js
const fs = require("fs");
const taxonomy = require("../../_data/tag-taxonomy.js");

module.exports = {
  eleventyComputed: {
    tags: (data) => {
      // Read raw file and strip frontmatter
      let raw = "";
      try {
        const file = fs.readFileSync(data.page.inputPath, "utf8");
        raw = file.replace(/^---[\s\S]*?---/, "");
      } catch (e) {
        // Fall back to whatever is available
      }

      const searchText = [data.title, data.description, raw].join(" ");
      const found = new Set(data.tags || []);

      for (const [, entries] of Object.entries(taxonomy)) {
        for (const [slug, patterns] of Object.entries(entries)) {
          for (const pattern of patterns) {
            if (pattern.test(searchText)) {
              found.add(slug);
              break;
            }
          }
        }
      }

      return [...found].sort();
    },
  },
};
```

Key notes:
- This merges cleanly with `posts.json` (layout/permalink/comments) in Eleventy's data cascade
- The global `eleventyComputed` (draft exclusion) sets `permalink` and `eleventyExcludeFromCollections` — no conflict with `tags`
- Existing frontmatter tags like `daily-digest` are preserved via the `Set` merge

## Step 3: Update the frontmatter validator

The `_validatePosts` collection (eleventy.config.js:251) validates that `tags` exists in raw frontmatter. With auto-tagging, computed tags won't satisfy this check if a post has no frontmatter tags.

Two options:
- **Option A**: Keep at least one tag in frontmatter (n8n already writes `daily-digest`) — no config change needed
- **Option B**: Remove `tags` from the required fields array since computed data now handles it

Recommend **Option A** — no code change, and `daily-digest` serves as a useful pipeline marker. Only fall back to Option B if we find posts without any frontmatter tags.

- [ ] The top 15 tags are meaningful (not dominated by one category)
- [ ] Tag pages don't include anything nonsensical
- [ ] Consider if the `tagCloud` exclude set needs any auto-tag additions

If a particular auto-tag is too noisy (appears on nearly every post), consider removing it from the taxonomy or adding it to the `tagCloud` filter's exclude set.

## Maintenance

- **New entity**: Add an entry to `_data/tag-taxonomy.js`, commit, done
- **Tag rename**: Change the key in the taxonomy — all posts pick up the new slug on next build
- **Tag audit**: Inspect built tag pages or run a build and check the tag cloud output
